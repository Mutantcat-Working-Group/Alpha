# Agent Note: 独立于子会话迁移每个会话

Status: implemented

[English](2026-09-19-session-local-subagent-migration.md) | 中文

## 问题

运行时 V3→V4 准备收集每个直接子会话的 descriptor 以补全父 catalog。这在打开父会话之前解码完整子日志，而无关的不可读头部也可能阻止完整成员分类。因此，一个损坏子会话就会阻断有效父历史。历史版本标识还对整个根目录取指纹，无关文件变化也使父缓存准备失效。

## 决策

JSONL 只迁移读写方显式打开的会话。它保留已有 catalog 事实，不读取子正文或收集跨会话证据。读 open 准备当前逻辑事件但不发布；写 open 校验所选源并独占发布不可变后继。公开版本标识和准备复用只依赖所选文件。前代文件字节保持不变。

发现机制合并父 catalog 事实与头部关系。没有 catalog 事实时，子代理服务返回未解析直接子条目；Web 从已有会话列表派生这些条目。菜单和分支刷新枚举头部，不请求子投影。选择子会话时打开自身历史，校验直接父归属和 descriptor，并解析模式与标签。此前地址不授予续接权限，输入区保持只读。子打开失败仅影响自身。显式程序读取和续接请求同样按需迁移选中会话；显式后代检查和批量迁移仍读取它们所请求的会话。

Catalog 仍是成功创建事实的持久化来源。未解析发现行既不是持久化事件，也不是投影值。无需新会话格式或持久化索引。离线夹具准备和 Preview 打包仍可显式提供子证据来补全 catalog，因为调用者已拥有该语料库。

本决策部分取代[已发布迁移](../architecture/2026-08-31-released-session-format-migrations.zh.md)中的运行时 catalog 前提与全库版本标识、[父 catalog](../architecture/2026-09-01-parent-owned-subagent-catalog.zh.md)中的仅靠 catalog 发现假设，以及 [Web 投影消费](../simplification/2026-09-08-web-subagent-catalog-projections.zh.md)中的未打开分支读取。它们的格式、创建、排序和传输决策仍有效。[不完整证据](2026-09-19-v3-incomplete-child-catalog-evidence.zh.md)继续约束可选离线补全。

## 考虑过的替代方案

**捕获子错误并继续回填。** 这仍解码所有健康子会话、隐藏失败，并在父后继发布时永久省略发现事实。

**传入空子集合而不改发现机制。** 这消除了迁移耦合，却让历史子会话从仅消费 catalog 的调用方消失。

**持久化占位 catalog 事件或另建子索引。** 未知模式和标签不是成功创建事实。第二份持久化索引增加写协调和修复工作，并不能改善基于头部的导航。

## 影响

显式直接子发现除物化 D 条 catalog 事实外，还枚举 N 个头部。它避免所有子正文解码，而普通父迁移没有依赖全库的准备工作。历史行最初可能显示 id 而非标签，且不能承诺可续接。无法解码的头部不能贡献导航行，但不会阻止打开另一个已知会话。

原始与压缩持久化回归覆盖 V0–V3、子损坏与未来格式、独立发布、前代不变，以及子变化期间父版本标识稳定。服务测试确认只观察父会话。Client 和 Host 测试验证未解析地址、选中子解码、模式解析与归属拒绝。正式 Web preset-migration 快照在损坏兄弟会话存在时往返父子代次，并检查只有显式打开的会话才迁移。
